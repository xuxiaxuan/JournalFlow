# 本地演示与验收

## 1. 启动与关闭

前提：MySQL 已运行，`journalflow` 库已按 README 初始化或完成增量迁移；本机可执行 Java 17+、Node.js 和 Maven；在 `frontend` 执行过 `npm.cmd install`。已有库不要重复执行含 DROP 的 `sql/schema.sql`。

在项目根目录：

```powershell
.\start-local.cmd
# 修改后端源码后，先停止再重新构建启动：
.\stop-local.cmd
.\start-local.cmd -Build
# 查看脚本管理的进程：
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/local.ps1 -Action status
```

访问 http://127.0.0.1:5173 。后端端口 8080。首次缺少 JAR 时脚本自动构建；已有 JAR 时默认复用，源码修改后需 `-Build`。构建跳过测试，不代表验收通过。

脚本在后台启动服务，不弹出额外窗口；重复执行复用已启动的同一进程。它核对 PID、启动时间和命令行，只关闭自身记录的进程，不停止 MySQL、不删除稿件或附件。端口被其他进程占用时会报错，不会自动强杀。日志为 `.runtime/backend.out.log`、`backend.err.log`、`frontend.out.log`、`frontend.err.log`，每次新启动会覆盖相应启动日志。

若启动失败，先查看日志：数据库不可用需检查 MySQL 服务及现有连接设置；依赖缺失需按 README 安装；端口冲突需手动确认占用者。状态检查在受限沙箱中可能需要进程查询权限，在普通本机 PowerShell 中运行即可。启动脚本不代替数据库备份。

## 2. 演示顺序

演示账号 `author1`、`editor1`、`reviewer1`、`admin` 的密码均为 `123456`，只用于本地模拟环境。

1. 匿名打开首页，检索“浏览器全流程验收”，进入文章详情并下载全文。首页仅检索本站已出版稿件，不联网搜索外部学术数据库。
2. 作者进入稿件列表，查看已出版验收稿的两个版本、修改说明和流程记录。需要现场演示新投稿时，用真实非空 PDF、DOCX 或 TeX 文件创建新稿件。
3. 编辑工作台完成形式审查并邀请 `reviewer1`；专家接受邀请、提交意见；编辑决定退修；作者上传修回稿后系统为原专家创建复审邀请。
4. 复审完成后编辑录用，作者签署当前版本版权，编辑填写卷期页码和模拟 DOI，进入出版加工后正式发布。模拟 DOI 只用于格式验证，不代表真实注册。
5. 编辑在 AI 中心展示输入、模型原始输出、版本关联和人工核对；元数据抽取确认后才写回，意见解释属于辅助建议，不自动作出审稿决定。
6. 使用“亮点功能演示”稿件展示正文版本差异、字段依据、逐条回应与编辑确认。它们是可选工具，不改变稿件状态或原有录用条件。

亮点样例准备（后端启动后，在 `frontend` 执行）：

```powershell
npm.cmd run demo:research
```

该脚本通过业务接口创建模拟数据，已有完整同名样例则复用。旧种子 PDF 为占位附件，不适合展示正文解析；请使用真实文件或亮点样例的 TeX 附件。

## 3. 测试复现

```powershell
# backend 目录：包含需要演示库的 MySQL 事务回滚测试
mvn.cmd '-Djournal.mysql.tests=true' test

# frontend 目录：后两项需要后端已启动，且 5193 端口空闲
npm.cmd test
npm.cmd run build
npm.cmd run demo:research
npm.cmd run test:e2e
# 单独选择执行，会保留新增模拟稿件及其流程记录
npm.cmd run test:full-flow
```

浏览器测试使用本机 Edge。日常冒烟测试会删除自己创建的临时草稿，但保留操作日志及专用亮点稿的回应历史；全流程测试不删除提交后的稿件，失败时也保留现场，控制台显示稿件 ID。只在模拟数据库执行，不要将它当作无副作用检查。

后端结果在 `backend/target/surefire-reports`；浏览器失败时保留 trace，完整流程截图在 `frontend/test-results-full`；日常冒烟结果在 `frontend/test-results`。这些是运行产物，下次运行对应测试可能覆盖。

## 4. 真实模型联调（尚待本机配置）

当前默认 `mock`，本轮没有真实模型密钥，也没有执行外部模型调用。新增的兼容协议测试只访问本地 HTTP 测试服务，不能证明真实模型的效果、服务可用性或事实一致性。

如已有兼容 Chat Completions 的模型服务，在本机 PowerShell 设置以下环境变量后，从**同一终端**启动项目；不要把密钥发到聊天或提交到仓库。按 Spring 环境变量命名规则，`api-key` 对应 `APIKEY`，`base-url` 对应 `BASEURL`。

```powershell
$env:JOURNAL_LLM_PROVIDER = 'openai-compat'
$env:JOURNAL_LLM_BASEURL = '你的服务基础地址（不含 /chat/completions）'
$env:JOURNAL_LLM_MODEL = '该服务支持的模型名'
$keyInput = Read-Host 'API Key' -AsSecureString
$env:JOURNAL_LLM_APIKEY = [System.Net.NetworkCredential]::new('', $keyInput).Password
.\start-local.cmd
```

须先停止旧服务；已运行的 Java 不会自动读取新环境变量。服务启动后可清除当前终端的密钥变量：`Remove-Item Env:JOURNAL_LLM_APIKEY`。服务进程已继承变量，仍可正常使用；配置没有写入源码。

仅上传模拟/脱敏稿件。依次发起 EXTRACT、SUMMARY、EXPLAIN，记录任务 ID、provider/model、来源版本、原始输出、失败重试和人工修订结果。核对题名、摘要、关键词有无缺失或补造，并检查是否混入给编辑的私密意见。填写已有的代表性样例评测报告，记录真实结果，不沿用 Mock 的通过结论。若服务不支持 `response_format: json_object` 或返回格式不同，需要单独适配，不视为已支持。

切回 Mock：停止服务，清除上述模型环境变量，再启动。没有真实模型联调证据前，答辩中应明确称为“接口与 Mock 流程已验证，真实模型效果待验证”。
